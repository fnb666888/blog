# 数据结构与算法速查

## 存储介质

| 类型 | 说明 |
|------|------|
| **内存** | 利用电容和晶体管存储数据，因电容会缓慢漏电，需要持续供电 |
| **固态硬盘 (SSD)** | 浮栅晶体管存储数据 |
| **机械硬盘 (HDD)** | 磁性盘片存储数据，磁头通过读取磁性读取数据 |

## 线性数据结构

### 数组 (Array)
- 在内存中占用一块连续的空间
- 支持通过下标进行随机访问（查找速度极快，O(1)）
- 插入和删除元素时需要移动大量数据

### 链表 (Linked List)
- 内存空间不连续，通过指针将节点连接起来
- 插入和删除只需修改指针（速度快）
- 查找时必须从头遍历（速度慢）

### 栈 (Stack)
- 操作受限的线性表，遵循**后进先出 (LIFO)** 原则
- 只能在栈顶进行压入 (Push) 和弹出 (Pop) 操作

### 队列 (Queue)
- 操作受限的线性表，遵循**先进先出 (FIFO)** 原则
- 从队尾添加元素，从队头移除元素

## 树形数据结构

### 二叉树 (Binary Tree)
- 每个节点最多只有两个子节点（左子节点和右子节点）

### 二叉搜索树 (BST)
- 在二叉树基础上增加排序规则（左小右大），能提高查找效率

### 堆 (Heap)
- 本质是完全二叉树
- 分为最大堆（父节点大于子节点）和最小堆（父节点小于子节点）

### 平衡二叉树 (AVL / 红黑树)
- 为了解决普通二叉搜索树退化成链表的问题，通过旋转保持树的平衡
- 确保查找复杂度维持在 O(log n)
- Java HashMap 底层就用到了红黑树

### B 树 / B+ 树
- 多路搜索树，节点可以有多个子节点
- 树比较"矮胖"，适合数据库索引

### 字典树 (Trie)
- 专门用于处理字符串
- 利用公共前缀节省空间

## 图结构

**组成**：由顶点（Node/Vertex）和边（Edge）组成

**分类**：
- 有向图（边有方向）
- 无向图（边无方向）
- 带权重图

## 哈希结构

### 哈希表 (Hash Table / 散列表)
- 通过哈希函数将键 (Key) 映射到数组的下标
- 实现 O(1) 级别的快速查找
- **哈希函数**：把任意长度的数据通过算法转化为固定长度的哈希值

### 并查集 (Disjoint Set Union)
- 高效处理不相交集合的合并及查询问题（例如判断两个人是否在同一个家族中）

### 跳表 (Skip List)
- 链表的升级版，通过建立多级索引来实现快速查找
- 是 Redis 中有序集合的核心实现之一

## 排序算法

### 初级排序算法

| 算法 | 说明 |
|------|------|
| **冒泡排序** | 从第一个元素开始，比较相邻的两个元素，每次循环会完成一个元素的正确排序 |
| **选择排序** | 每次循环从未排序数据中找出正确的数据放入已排序末尾 |
| **插入排序** | 每次循环将一个未排序数据插入到已排序数据中 |

### 高效排序算法

| 算法 | 说明 |
|------|------|
| **归并排序** | 不断地将数组一分为二，使用双指针法进行合并 |
| **快速排序** | 选择基准后将数组一分为二，并重复这个过程 |

## 最小生成树

在带权重的无向图中找到一条包含所有顶点的、所有边权重最小的树。

| 算法 | 说明 |
|------|------|
| **Kruskal 算法** | 按边权重从小到大排序，逐一添加不构成环的边 |
| **Prim 算法** | 从任意顶点开始，每次选择与当前树连接的最小权重边 |
